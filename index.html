Case Study: RESTful BI Core API

The Challenge

Analytical dashboards experienced devastating database thread pool exhaustion and severe latency bottlenecks when reading aggregate views under highly concurrent query streams.

The Solution

Built an ultra-low-latency ASP.NET Core Minimal API utilizing Dapper for zero-overhead SQL mapping. Implemented the **Lookaside Cache pattern** via IMemoryCache and resolved a database connection pool exhaustion (Cache Stampede) bottleneck under high load. This was achieved by introducing a **Double-Check Locking pattern** using a static ConcurrentDictionary<string, SemaphoreSlim> to serialize database hits during cold starts.

Double-Check Locking Cache Pattern TryGetValue → SemaphoreSlim.WaitAsync() → TryGetValue (Again) → Dapper Query → Cache.Set()

Key Architecture & Metrics

  • P(95) Latency of 0.66 ms: Flawless sub-millisecond responsiveness under massive concurrent load.
  • 6,800+ Requests Per Second: Sustained high throughput under extreme stress test conditions.
  • 1,000 Concurrent VUs: Handled massive concurrent virtual users with 100% request success rate (HTTP 200) and zero thread pool exhaustion.
  • Zero Log Overhead: Stripped blocking Kestrel loggers to eliminate internal logging bottlenecks.
